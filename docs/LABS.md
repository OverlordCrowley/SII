## ЛР 3 Области применения ИИ

**Неделя 4. Цель:** выбрать предметную область и создать базовую
модель представления знаний для диагностики компьютера.

### Теоретическое введение

Предметная область определяет, какие объекты, свойства и отношения
нужно представить в интеллектуальной системе. Хорошо структурированная
область имеет понятные типы объектов, формализуемые признаки и достаточно
устойчивые связи. Плохо структурированная область содержит неоднозначные
описания, противоречивые наблюдения и решения, зависящие от контекста.
Диагностика компьютера частично структурирована: компоненты и типичные
симптомы перечислить легко, но одинаковый симптом может иметь несколько
причин. Поэтому программа формирует возможные гипотезы и сохраняет
неопределённость, а не объявляет любую гипотезу окончательным диагнозом.

База знаний содержит сведения о симптомах, компонентах, гипотезах и
способах проверки. Семантическая сеть представляет объекты узлами,
а отношения — подписанными направленными дугами. В выбранной области
накопитель является частью компьютера, проблема диска затрагивает
накопитель, а щелчки диска указывают на возможную проблему диска.
Эти связи дают понятную структуру для поиска. Продукционные правила
добавляют условную зависимость: при подтверждённых симптомах появляется
новая гипотеза. Сеть и правила дополняют друг друга, поскольку путь
в графе показывает связь объектов, а правило задаёт условие вывода.
Для всех моделей используются одинаковые идентификаторы объектов,
чтобы их можно было объединить в одной программе.

### Реализация и примеры

Создан `data/knowledge.json`: 18 наблюдаемых симптомов, 7 гипотез,
23 правила, 15 фреймов, 22 узла и 22 связи. Загрузка выполняется
функцией `load_knowledge` в `knowledge.py`.

```python
from pc_assistant.knowledge import load_knowledge
k = load_knowledge()
print(k["diagnoses"]["disk_failure"]["label"])
print(k["frames"]["office_pc"]["slots"])
```

Результат: «Возможная проблема накопителя» и
`{'name': 'Офисный ПК', 'ram_gb': 16}`. Третий запрос к исходному
графу показывает связь `['storage', 'part-of', 'computer']`.

**Вывод:** сформирована единая формализованная база. Реальная
диагностическая неоднозначность учтена через возможные гипотезы.
Коммит этапа: `feat(w04): add computer knowledge base`.

1. **Что такое хорошо структурированная предметная область?** Область,

2. **Что такое модель представления знаний?** Формат и операции,

## ЛР 4 Логическая модель представления знаний

**Недели 5–6. Цель:** определить логические факты и правила, реализовать
операции AND, OR, NOT и объяснение результата.

### Теоретическое введение

Логическая модель описывает знания высказываниями и связями между ними.
Высказывание имеет значение истинности. Предикат выражает свойство
объекта или отношение между объектами и становится высказыванием после
подстановки аргументов. В проекте используется логика высказываний:
`high_temp` обозначает наблюдение о перегреве текущего компьютера.
Отдельные наблюдения соединяются конъюнкцией AND, дизъюнкцией OR и
отрицанием NOT. Скобки задают группировку, а стандартный приоритет
операций позволяет однозначно разобрать выражение.

В классической таблице истинности все переменные заданы. В диалоге
часть симптомов может быть неизвестна, поэтому используется третье
значение U. Отрицание U остаётся U. Ложная посылка делает конъюнкцию
ложной, даже если другая посылка неизвестна; истинная ветвь делает
дизъюнкцию истинной. Такой подход не позволяет заменить отсутствие
наблюдения отрицанием симптома. Правило имеет условие и положительное
заключение. Обратный вывод выбирает цель, ищет подходящие правила
и рекурсивно проверяет их посылки. Исходный факт завершает доказательство,
а обнаруженный цикл прерывает рекурсию. Если доказательство отсутствует,
цель остаётся неизвестной. Для объяснения сохраняются правило и только
те посылки, которые действительно подтверждают выбранную ветвь.

### Реализация и примеры

Файл `logic.py` содержит безопасный парсер AST, вычисление выражений,
таблицу истинности и `LogicalEngine`. Пользовательский текст не
передаётся в `eval`. Отрицание выводимых атомов запрещено.

```python
from pc_assistant.logic import evaluate, LogicalEngine
from pc_assistant.knowledge import load_knowledge
print(evaluate("high_temp AND (fan_loud OR shutdowns)",
               {"high_temp": True, "fan_loud": True}))
print(evaluate("NOT beeps", {}))
engine = LogicalEngine(load_knowledge()["rules"])
print(engine.query("ram_failure",
                   {"power_on": True, "screen_on": False, "beeps": True}))
```

Результаты: `True`, `None`, `True`. Для третьего случая объяснение
содержит R03 и вложенное R02 с исходным `screen_on=false`.
Таблица `a AND (b OR NOT c)` имеет 8 строк и 3 истинных результата.

**Вывод:** логическая модель корректно работает с отрицаниями и
неполной информацией. Этапы сохранены коммитами w05 и w06.

### Контрольные вопросы

1. **Что такое логическая модель знаний?** Представление знаний
   формулами с определёнными правилами вычисления и вывода.
2. **Что такое высказывание и предикат?** Высказывание утверждает факт;
   предикат задаёт свойство или отношение с параметрами.
3. **Какие логические операции используются?** AND, OR, NOT,
   а для записи правила — связь условия с заключением.

## ЛР 5 Продукционная модель представления знаний

**Неделя 7. Цель:** создать не менее 10 правил «если-то» и реализовать
прямой вывод для диагностических сценариев.

### Теоретическое введение

Продукционная система разделяет знания и механизм их применения.
Знания задаются правилами «если условие, то заключение или действие».
Рабочая память хранит наблюдения и уже полученные заключения. Механизм
вывода сопоставляет условия правил с рабочей памятью, выбирает
подходящее правило и добавляет результат. При прямом выводе система
начинает с наблюдений и последовательно получает доступные следствия.
При обратном выводе сначала выбирается цель. Для консультации полезен
прямой вывод, поскольку пользователь сообщает симптомы и ожидает
все обоснованные гипотезы.

Если несколько правил подходят одновременно, нужен понятный порядок
разрешения конфликтов. В проекте он определяется числовым приоритетом,
а при одинаковом приоритете — идентификатором. Уже выведенное заключение
не добавляется повторно. Такая монотонная система достигает неподвижной
точки, когда проход по правилам не меняет рабочую память. Новые факты
не удаляются и не опровергают старые. Для сохранения этого свойства
отрицания допускаются только над исходными наблюдениями. Система
объяснений сохраняет основания срабатывания каждого правила и может
раскрывать промежуточные заключения. Продукционный подход удобен для
добавления новых проверяемых знаний, однако требует контроля
противоречий, неполных условий и дублирующих правил.

### Реализация и примеры

`ProductionEngine` в `production.py` применяет 23 правила. Среди них
16 диагностических и промежуточных правил и 7 заключений о проверках.

```python
from pc_assistant.production import ProductionEngine
from pc_assistant.knowledge import load_knowledge
engine = ProductionEngine(load_knowledge()["rules"])
a = engine.run({"internet_down": True, "wifi_disconnected": False})
b = engine.run({"high_temp": True, "fan_loud": True})
print([event["rule"] for event in a["trace"]])
print([event["rule"] for event in b["trace"]])
```

Результат первого случая: R10, R11, R22. Во втором: R05, R06, R20.
Для пустого набора фактов трасса пуста. Программа достигает
неподвижной точки и возвращает список новых фактов и объяснения.

**Вывод:** реализована продукционная система с цепочками вывода
и воспроизводимым порядком правил. Коммит этапа — w07.

### Контрольные вопросы

1. **Что такое продукционная модель?** Набор правил, рабочая память
   и механизм применения правил.
2. **Из чего состоит правило?** Из условия и заключения или действия.
3. **Как происходит вывод решения?** Система проверяет условия,
   добавляет следствия и повторяет процесс до отсутствия новых фактов.

## ЛР 6 Фреймы для представления знаний

**Недели 8–9. Цель:** описать объекты и свойства, реализовать
наследование, поиск и изменение слотов.

### Теоретическое введение

Фрейм представляет объект или типичную ситуацию через набор слотов.
У каждого слота есть имя и значение. Слоты могут содержать свойства,
связи и значения по умолчанию. Фреймы типов задают общую структуру,
а фреймы экземпляров описывают конкретные объекты. Иерархия позволяет
потомку наследовать свойства предка: у всех компьютеров может быть
общая ОС по умолчанию, а конкретный экземпляр переопределяет объём
оперативной памяти. Это уменьшает повторение одинаковых данных и
делает структуру предметной области более понятной.

Наследование требует определённого порядка обработки. В проекте
сначала собираются слоты корня, затем родителя и экземпляра. Более
близкое локальное значение заменяет унаследованное. Вместе с итоговым
значением сохраняется его источник, чтобы пользователь понимал,
откуда оно пришло. Изменение слота экземпляра создаёт локальное
переопределение и не меняет предка. Поиск сравнивает эффективные
унаследованные значения. Цикл наследования и отсутствующий родитель
являются ошибками модели. Пользовательские изменения должны переживать
перезапуск, поэтому фреймы сериализуются отдельно от исходной базы.
В сравнении с семантической сетью фрейм удобнее для просмотра всех
свойств одного объекта, а граф — для поиска цепочек отношений.

### Реализация и примеры

`FrameStore` содержит 15 исходных фреймов, описывает источники слотов,
создаёт экземпляры и сохраняет пользовательские изменения.

```python
from pc_assistant.frames import FrameStore
from pc_assistant.knowledge import load_knowledge
store = FrameStore(load_knowledge()["frames"])
print(store.get("office_pc", "ram_gb"))
print(store.get("student_laptop", "has_battery"))
store.set("office_pc", "ram_gb", 24)
print(store.get("computer", "ram_gb"))
```

Результаты: `16`, `True`, `8`. Локальное значение офисного ПК стало
24 ГБ, родитель сохранил 8 ГБ. Поиск `has_battery=true` находит
`laptop` и `student_laptop`. Повторная загрузка сохранённых фреймов
возвращает изменённое значение. Нулевой объём RAM отклоняется.

**Вывод:** реализованы наследование, локальные переопределения,
поиск и постоянное хранение. Коммиты этапов — w08 и w09.

### Контрольные вопросы

1. **Что такое фрейм?** Структура знаний об объекте или ситуации
   с именованными слотами.
2. **Что такое слот?** Поле фрейма для свойства или связи и его значения.
3. **Что такое наследование?** Получение значений от предков
   с возможностью локального переопределения.

## ЛР 7 Семантические сети

**Неделя 10. Цель:** создать сеть с не менее чем 10 узлами и 10
связями и реализовать поиск пути и связанных объектов.

### Теоретическое введение

Семантическая сеть описывает знания в форме графа. Узлы обозначают
объекты, понятия или состояния. Дуги имеют направление и имя
отношения. `is-a` описывает принадлежность типу, `part-of` — связь
части и целого. В диагностическом проекте также нужны отношения
`indicates` между симптомом и гипотезой и `affects` между гипотезой
и компонентом. Различение отношений важно: связь «часть компьютера»
не равнозначна выводу о неисправности этого компонента.

Запрос к графу может искать непосредственных соседей или путь
между двумя объектами. Для невзвешенного графа поиск в ширину BFS
находит кратчайший путь по числу рёбер. Он использует очередь и
множество посещённых узлов. Последнее предотвращает бесконечный обход
при наличии циклов. Поиск в глубину DFS также позволяет найти путь,
но без дополнительных условий не гарантирует минимальную длину.
Направление дуги является частью значения связи. В проекте обратный
обход разрешается отдельным параметром и помечается как обратный,
чтобы не менять смысл сохранённых отношений. Путь в семантической
сети объясняет связь объектов, однако сам по себе не доказывает
диагноз. Для доказательства используются условия продукционных правил.

### Реализация и примеры

`SemanticNetwork` в `network.py` хранит 22 узла и 22 связи, позволяет
добавлять новые объекты, фильтровать отношение и выбирать глубину.

```powershell
python -m pc_assistant network path disk_noise storage
python -m pc_assistant network path laptop device
python -m pc_assistant network path device laptop
```

Первый путь состоит из `disk_noise —indicates— disk_failure`
и `disk_failure —affects— storage`. Второй проходит через `computer`
и имеет длину 2. Третий не найден в направленном режиме;
`--undirected` находит два обратных ребра `inverse:is-a`.

**Вывод:** размер сети соответствует заданию; BFS, направление
и фильтрация проверены. Коммит этапа — w10.

### Контрольные вопросы

1. **Что такое семантическая сеть?** Граф представления знаний
   с объектами и типизированными отношениями.
2. **Из каких элементов она состоит?** Из узлов и подписанных дуг.
3. **Какие алгоритмы поиска пути используются?** BFS, DFS,
   а при наличии весов — алгоритмы, учитывающие стоимость рёбер.

## ЛР 8 Вероятностный подход и нейронные сети

**Недели 11–12. Цель:** создать датасет, обучить классификатор и
простую нейросеть, оценить результаты на отдельной тестовой части.

### Теоретическое введение

Вероятностная модель ранжирует гипотезы по наблюдаемым данным.
Наивный байесовский классификатор использует априорные вероятности
классов и вероятности признаков при заданном классе. Наивность
заключается в предположении условной независимости признаков.
Для бинарных симптомов подходит модель Бернулли. Сглаживание Лапласа
предотвращает нулевое правдоподобие признака, который не встретился
в обучающем наборе. Расчёт в логарифмах снижает риск численного
обнуления произведений маленьких вероятностей.

Искусственная нейронная сеть представляет обучаемое преобразование
входных признаков. В MLP скрытый слой применяет нелинейную функцию
активации, а выходной softmax нормализует оценки классов. Обучение
минимизирует кросс-энтропию градиентным спуском. Данные разделяются
на train для изменения весов, validation для выбора версии модели
и test для итоговой оценки. Одинаковые векторы признаков объединяются
в группы и не пересекают части, чтобы исключить простую утечку.
Accuracy показывает долю правильных ответов. Precision оценивает
точность предсказаний класса, recall — найденную долю истинных
случаев, F1 объединяет их. Macro F1 одинаково учитывает каждый класс.
Синтетические данные удобны для воспроизводимого учебного эксперимента,
но качество на них не характеризует диагностику реальных компьютеров.

### Реализация и результаты

`dataset.py` генерирует 180 примеров каждого из 7 классов, seed 42.
Файл содержит 1 260 записей, 18 признаков, метку, split и группу.
Получено 840 train, 176 validation и 244 test.

В `ml.py` реализованы BernoulliNB и MLP 18–16–7. Градиенты MLP
вычисляются вручную на NumPy. Обучение длится 600 эпох с шагом 0,18,
лучшая версия выбрана по validation на эпохе 591.

| Модель | Accuracy test | Macro F1 test |
|---|---:|---:|
| Bernoulli Naive Bayes | 95,90% | 0,9592 |
| MLP 18–16–7 | 96,31% | 0,9634 |

Подробности по классам и матрицы ошибок приведены в `MODEL_RESULTS.md`.
Запрос с `high_temp=true`, `fan_loud=true`, `shutdowns=true`
даёт первым классом `overheating` у обеих моделей. При одном
известном симптоме рейтинг скрыт. Повторный расчёт по сохранённым
весам совпадает с записанными метриками.

**Вывод:** обе модели обучены и оценены. Их высокие показатели
относятся только к заданным синтетическим профилям. Этапы — w11 и w12.

### Контрольные вопросы

1. **Что такое искусственная нейронная сеть?** Модель из связанных
   вычислительных узлов с обучаемыми параметрами.
2. **Чем Байес отличается от нейросети?** Байес явно оценивает
   вероятности классов и признаков при предположении независимости;
   нейросеть обучает составное нелинейное преобразование.
3. **Какие метрики используются?** Accuracy, precision, recall,
   F1, macro F1 и матрица ошибок.

## ЛР 9 Экспертные системы

**Неделя 13. Цель:** объединить знания, правила и механизм вывода
в объяснимую консультационную программу.

### Теоретическое введение

Экспертная система применяет формализованные знания предметной области
для решения задач, которые обычно требуют специалиста. Основные
компоненты — база знаний, механизм вывода, рабочая память, интерфейс
и подсистема объяснений. База знаний хранит общие правила и сведения
об объектах. Рабочая память содержит наблюдения текущего случая.
Механизм вывода связывает наблюдения с заключениями. Подсистема
объяснений позволяет проверить, почему система предложила конкретную
гипотезу. Это особенно важно, когда разные неисправности имеют
похожие симптомы.

При создании экспертной системы сначала выделяют область и цель,
затем собирают знания, формализуют их, реализуют вывод и проверяют
типичные и пограничные случаи. Прямой вывод подходит для обработки
набора введённых симптомов, а обратный — для проверки отдельной
гипотезы. Согласованность двух способов служит полезной проверкой,
но не заменяет экспертную оценку самих правил. Фреймы предоставляют
контекст устройства и свойства компонента, а семантическая сеть
показывает отношения между объектами. Классификаторы добавляют
учебный рейтинг. Объединение этих компонентов требует одинаковых
идентификаторов и явного разделения доказанного вывода и оценок
обучаемых моделей. В проекте итоговая консультация сохраняет
объяснение, даже когда модельный рейтинг отличается от правил.

### Реализация и примеры

`ExpertSystem` в `expert.py` загружает базу, локальное состояние,
вывод и модели. Метод `diagnose` возвращает гипотезы, трассу,
фрейм компонента, путь в сети, вопросы и модельные оценки.

| Наблюдения | Гипотеза | Правила |
|---|---|---|
| Не включается, вентиляторы не вращаются | Питание | R01, R17 |
| Перегревается, кулер шумит | Охлаждение | R05, R06, R20 |
| Нет интернета, Wi-Fi подключен | Сеть | R10, R11, R22 |

Для каждой полученной гипотезы выполнена обратная логическая
проверка. Пустой набор наблюдений не создаёт гипотез и вызывает
уточняющие вопросы.

**Вывод:** все модели объединены в общую консультацию. Коммит — w13.

### Контрольные вопросы

1. **Что такое экспертная система?** Программа, применяющая знания
   предметной области и механизм вывода для консультации или решения.
2. **Что такое база знаний и механизм вывода?** База хранит правила
   и сведения, механизм выводит заключения по ним и наблюдениям.
3. **Чем отличаются прямой и обратный вывод?** Прямой начинает
   с фактов, обратный — с цели и её возможных доказательств.

## ЛР 10 Итоговый ИИ-помощник

**Недели 14–15. Цель:** реализовать ввод запроса и ответа, объединить
модули, подготовить документацию и демонстрацию для защиты.

### Теоретическое введение

Итоговое приложение связывает интерфейс и интеллектуальные модули
в одну воспроизводимую программу. Пользователь сообщает наблюдения,
анализатор выделяет факты, механизм вывода получает гипотезы,
а генератор ответа объясняет результат. При ограниченном словаре
необходимо явно показывать, сколько симптомов распознано, и не
создавать факты из неизвестных фраз. Противоречивые описания одного
симптома требуют уточнения. Вопросы помогают дополнить рабочую
память, сохраняя различие между «да», «нет» и «неизвестно».

Комбинированный подход использует сильные стороны разных моделей.
Правила дают явные основания, фреймы группируют свойства объекта,
сеть описывает связи, а обучаемые модели сравнивают статистические
профили. Одновременно интеграция создаёт требования к общим
идентификаторам, форматам данных и обработке ошибок. Тестирование
проверяет функции и сценарии целиком, включая консольный процесс,
сохранение локальных изменений, циклы и неполный ввод. Документация
должна позволять воспроизвести демонстрацию и отличать готовую
реализацию от действий, которые предстоит выполнить студенту,
например публикации и личной защиты. История Git сохраняет реальные
этапы изменений. Презентация объясняет задачу, архитектуру, алгоритмы,
результаты и ограничения без необходимости читать весь исходный код.

### Реализация и примеры

`Assistant.ask` анализирует русские фразы и формирует ответ.
CLI поддерживает `ask`, `chat`, `demo`, работу со всеми моделями
знаний и повторное обучение. `run.bat` упрощает запуск Windows.
Подготовлены семь демонстрационных запросов, README, описание
архитектуры, результаты, история этапов и презентация.

```powershell
python -m pc_assistant demo
python -m pc_assistant ask "Компьютер включается, черный экран, пищит"
python -m pc_assistant ask "Компьютер включается, черный экран"
python -m unittest discover -s tests -v
```

Первый конкретный запрос выводит гипотезу памяти с объяснением.
Второй требует уточнить звуковые сигналы. Автоматические тесты
проверяют все семь сценариев и существенные пограничные случаи.
Внутреннее ревью и исправления описаны в `CODE_REVIEW.md`.

**Вывод:** готова единая программа и комплект материалов.
Коммит интерфейса — w14; итоговый коммит — w15. Для выполнения
организационной части студент заполняет личные данные, публикует
репозиторий и проводит защиту. Эти действия не выдаются за выполненные.

### Контрольные вопросы

1. **Какие структуры удобны для фреймов и сетей?** Словари со
   слотами и родителем для фреймов; словарь узлов и список рёбер
   или списки смежности для графа.
2. **Как хранить базу знаний?** Отдельным структурированным файлом
   с согласованными ID, проверкой формата и контролем версии.
3. **Как проверить интеллектуальную программу?** Сопоставить
   результаты с ожидаемыми сценариями, проверить неполный и
   противоречивый ввод, границы алгоритмов и воспроизводимость данных.
