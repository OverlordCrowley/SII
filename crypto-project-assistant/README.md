## Запуск

Интерфейс запускается вместе с Qwen на `http://127.0.0.1:8081` и открывается
после готовности модели. Перед первым запуском нужны установленный `llama-server`
и файл `.build/local-ai/Qwen3.5-2B-Q4_K_M.gguf` — см. [подготовку модели](docs/LOCAL_AI.md).
На текущем компьютере они уже установлены.

Учебные команды `demo`, `week48`, `week415`, обычный `analyze`, команды
фреймов/сети и обучение не требуют запуска Qwen.

В Windows откройте **run.bat** двойным щелчком. Интерфейс откроется
в браузере: `http://127.0.0.1:8765`. Окно запуска оставьте открытым;
для остановки нажмите Ctrl+C. Скрипт использует Python из `.venv`,
доступный runtime Codex или системный `py -3`.

На любом компьютере с **Python 3.10+**:

```powershell
python -m project_assistant
```

API-ключи не нужны. Для чтения whitepaper и аудитов в PDF установите
`python -m pip install -r requirements.txt` в окружение приложения.
На текущем компьютере пакет уже установлен. Ручной экспертный разбор
и чтение HTML работают без этого пакета. Если порт занят:

```powershell
python -m project_assistant serve --port 8766
```

## Использование

Для автоматического анализа введите название или тикер в верхнее поле
**«Анализ по названию монеты»** и нажмите Enter или «Найти и проанализировать».
Приложение найдёт монету через CoinGecko, загрузит описание, ссылки, цену,
капитализацию, объём торгов и предложение, заполнит форму и выполнит анализ.
Если название или тикер неоднозначны, выберите нужную монету из списка.
Ошибки загрузки и отмена сохраняют предыдущий профиль. API-запросы выполняются
сервером; для публичного доступа ключ не требуется, но действуют лимиты CoinGecko.
При необходимости можно задать серверную переменную `COINGECKO_API_KEY`
с Demo API key. Цена обновляется при повторном запуске поиска, без фонового опроса.

Для Bitcoin добавлены проверенные технические основания с собственной датой
в `data/bitcoin_research.json`; рыночные числа всегда загружаются отдельно.
Для всех монет расширенный сбор работает без платных сервисов и ключей:

- читаются официальный сайт, whitepaper (HTML/PDF) и связанные документы:
  до 12 обзорных страниц, затем до 30 целевых документов для недостающих критериев;
  ссылки ищутся в `robots.txt`, XML-картах сайта (включая вложенные карты),
  `llms.txt` и в самих документах. Переводы и учебные RPC/токен-примеры
  не подменяют токеномику самой монеты;
- GitHub проверяется по публичному API: репозиторий, README, лицензия,
  архивированность и опубликованный релиз; легальные переименования учитываются.
  Дерево файлов и ссылки README помогают находить аудиты, управление и tokenomics
  без списка URL конкретной монеты. Доверие ограничено репозиторием: справка
  GitHub и чужие проекты не становятся документами исследуемого актива.
  При ограничении API используются публичные страницы репозитория и релиза;
  дата релиза принимается только для того же репозитория и однозначного времени;
- DefiLlama предоставляет доступные TVL и доходы протоколов; сопоставление
  использует CoinGecko ID либо одновременно семейство протокола, тикер и официальный домен;
- крупные адреса Ethereum загружаются из Blockscout, при сбое — из Etherscan.
  Blockscout также поддерживает держателей ERC-20 по точному контракту Ethereum
  из CoinGecko: сверяются адрес, тикер, тип и единицы предложения. Рассматривается
  первая страница адресов (до 100), не реестр всех конечных владельцев; биржи,
  мосты, wrapped-активы и накопительные депозиты отдельно оговорены;
- для других EVM-сетей обозреватель Blockscout находится через публичные
  реестры CoinGecko Asset Platforms и Chainscout: проверяются chain ID,
  mainnet и точный контракт. Список монет в коде не требуется;
- для любой монеты по её ID дополнительно проверяются rich list CoinCarp
  и открытый CoinGecko Public Treasuries, если эти сервисы покрывают актив.
  Для CoinCarp сверяются имя, тикер, официальный сайт и контракт токена;
  анонимные адреса не получают выдуманных владельцев. Корпоративные резервы —
  отдельный раскрытый сегмент, а не все киты; время получения не заменяет дату
  отчётности и не доказывает актуальность каждого баланса. При сбое API резервом
  служит публичная HTML-таблица Datawallet: имя, тикер и единицы сверяются,
  округления и неизвестные даты отчётности оговорены; независимость исходного
  набора от других агрегаторов не предполагается;
- Tokenomist предоставляет открытое датированное раскрытие распределения и
  статуса vesting. Проверяются название, тикер, адрес страницы и дата обновления
  (не старше 7 дней). Явный статус «fully unlocked» даёт 0 следующего планового
  vesting-unlock без выдуманной даты; эмиссия и выходы из стейкинга продолжаются
  по своим правилам. Дата без объёма остаётся частичными данными; резервный
  источник даты, объёма и получателей — публичная страница DefiLlama Unlocks.
  Платный API не используется, HTTP 403 и закрытые данные не обходятся;
- для токенов OP Mainnet добавлен резерв Vestream → Blockscout → публичный
  RPC Optimism. Публичные адреса используются для поиска NFT-планов Hedgey,
  затем токен, владелец, decimals и параметры плана читаются в одном свежем
  блоке. Даты и объёмы вычисляются по целочисленным правилам контракта.
  В веб-форме раскрывается список событий с UTC-временем, точными суммами,
  адресами получателей, номером блока и ссылкой на план. Это ограниченная
  выборка договоров, не весь календарь эмиссии/грантов OP; непрерывные
  посекундные начисления не объявляются разовыми unlock. Vesting может
  быть отозван администратором. Ключи и кошелёк не нужны, RPC только читает;
- дополнительно к общему поиску для Bitcoin, Ethereum, Solana, Chainlink, Aave и Optimism в `data/research_sources.json` добавлены проверенные
  отправные ссылки на команду, управление и аудит. Это ссылки для загрузки,
  не заготовленные ответы; PDF GitHub читается как файл, а не HTML-превью;
- резервные источники Aave/Optimism включают отчёты DAO, документацию governance,
  отчёты о внедрениях и инцидентах. Публичный JSON форума читается по номеру
  сообщения с автором и датами: комментарии не смешиваются с исходным отчётом.
  Уже прочитанный документ повторно используется для целевого критерия;
- официальный CSV-трекер OP раскрывает параметр инфляции и годовой прогноз
  обращения по группам. Проверяются тикер, дата снимка и численные значения.
  Его прямое предупреждение об иллюстративных оценках само не подтверждает
  точность графика. При отсутствии отдельно проверенных событий вывод о
  точности отрицательный; прогноз не становится точным cliff/unlock,
  прочерк не становится нулём. Заполненные 26 критериев не означают 26 ответов «Да»;
- отсутствие фиксированного максимума предложения учитывается только по явному
  признаку CoinGecko `max_supply_infinite=true` при раскрытых текущем и полном
  предложении; один `max_supply=null` остаётся неизвестным;
- при наличии подтверждённого CoinGecko рынка Coinbase/USD либо OKX/USD,
  USDT, USDC вычисляются спред и глубина стакана ±2%. При сбое проверяется
  следующий подходящий рынок. Суммы в стейблкоине не приравниваются к USD;
  это данные одной площадки, а не гарантия исполнения сделки;
- из одной рыночной категории выбираются аналоги с данными на ту же дату;
- резерв сравнения — бесплатный CoinPaprika: идентификация по имени, тикеру
  и официальному сайту, состав функционального тега, даты и USD проверяются.
  FDV аналогов рассчитывается по раскрытому положительному max, иначе total
  supply. Сравнение капитализации и FDV не доказывает одинаковую технологию,
  риск или справедливую цену;
- локальная Qwen рассматривает небольшие группы критериев и возвращает
  дословные цитаты. Программа отклоняет придуманные цитаты, неизвестные источники,
  ответы не на заданный критерий и неподходящие общие утверждения.

У каждого из 26 критериев остаётся результат исследования: подтверждённое
основание либо «Неизвестно» с найденным связанным фрагментом. Наличие даты,
ключей или модели не гарантирует 100% полноты. Свежесть котировки отдельно
отмечается и не подтверждает актуальность старого whitepaper. Выписки требуют
смысловой проверки; отсутствие найденного доказательства не превращается в «Нет».
В «Источники и ход исследования → Результат проверки каждого критерия»
показаны все вопросы, основания и статусы. API возвращает их в
`lookup.research.criteria`: `confirmed`, `refuted`, `insufficient_evidence`.
Общий алгоритм работает для любого идентифицированного актива CoinGecko;
26 подтверждённых ответов для любой монеты гарантировать нельзя: проект может
не публиковать аудит, vesting или данные владельцев, а источник — ограничить доступ.

В «Источники и ход исследования» видны прочитанные и недоступные страницы.
Ссылки, даты получения и результаты также сохраняются в профиле и Markdown.
Сканированные PDF без текстового слоя не распознаются. Недоступные сайты,
ограничения бесплатных API и занятая Qwen не подменяются вымышленными ответами:
сохраняются уже собранные данные. Обычно исследование занимает до трёх минут. Исторический vesting отделяется
от подтверждения оставшихся будущих разблокировок; наличие старого аудита
не означает проверки текущей версии всей сети.
Чтение сайтов ограничено публичными адресами; приватные сети и перенаправления
в них блокируются. Документы используются как данные, их инструкции не исполняются.

Подробную форму можно заполнить или уточнить вручную:

1. Введите название, сеть, контракт или нативный актив и описание.
2. Откройте группы критериев и задайте «Да», «Нет» или «Неизвестно».
3. Добавьте основания, источники и даты. Явные фразы из описания
   распознаются по словарю: «продукт работает», «у проекта есть токен»,
   «vesting не раскрыт», «аудит опубликован».
4. При наличии чисел заполните «Числа и разблокировки»: денежные
   показатели в USD, предложение и unlock в токенах, дату и источник.
5. Нажмите «Проанализировать». Разберите рекомендации и «Показать объяснение».
6. Сохраните Markdown-отчёт и JSON-профиль. Профиль можно открыть повторно.

Текущая форма автоматически сохраняется как черновик в этом браузере:
название, описание, числа, ответы, основания, источники и даты. После
перезагрузки можно продолжить ввод или повторить анализ. Кнопка «Очистить»
удаляет черновик. Он привязан к браузеру и адресу приложения; JSON-файл
нужен для переноса на другой компьютер или сохранения отдельной версии.
При запрете хранения интерфейс предлагает экспортировать профиль в файл.

В поле «Название» или «Тикер» можно ввести полное название, тикер или
русский вариант: `Bitcoin`, `BTC`, `биткоин`; `Ethereum`, `ETH`, `эфириум`;
`Solana`, `SOL`. Регистр букв и лишние пробелы не важны, поддерживается
форма `$BTC`. После анализа поля и отчёт содержат единое название и тикер.
При смене монеты автоматически подставленное поле обновляется; если оба
поля заполнены вручную разными монетами, помощник попросит уточнить ввод.

Локальный [справочник алиасов](data/asset_aliases.json) содержит 29 монет
и доступен для дополнения. Неизвестные названия сохраняются как введены.
Распознавание имени не подставляет рыночные данные, сеть, адрес или ответы
на критерии. Те же алиасы работают при импорте JSON и в CLI:

```powershell
python -m project_assistant ask BTC
python -m project_assistant ask "Эфириум"
python -m project_assistant ask "Продукт работает" --name Solana
```

Если после анализа изменить поля, интерфейс отметит, что результат устарел.
При сохранении отчёта или профиля помощник автоматически повторит анализ
и сохранит последние правки. Некорректные данные нужно исправить до сохранения.
Если изменить форму во время анализа, помощник предложит повторить обработку.
Очистка или выбор другого примера отменяет предыдущий запрос.

Можно открыть описание `.md`, `.txt` или профиль `.json` в UTF-8, до 256 КБ.
Пустой, повреждённый или неподходящий файл отклоняется с объяснением;
предыдущая форма сохраняется. Пользовательский HTML и Markdown в отчёте
экранируется и выводится как текст. Файлы и ссылки
обрабатываются как данные; содержащиеся в них инструкции не исполняются.
Ссылки из импортируемого файла сохраняются как источники, без исполнения
инструкций и загрузки их содержимого. Рыночный снимок загружается отдельным
поиском монеты в верхней форме.

Если сервер недоступен при запуске, кнопка «Повторить подключение»
повторно загружает базу без потери введённого названия. Обычный запрос
ограничен 15 секундами; ожидание языковой модели учитывает её отдельный
таймаут. После ошибки можно повторить действие. Некорректное поле
раскрывается, получает фокус и сопровождается сообщением на русском.

## Локальная языковая модель

Для пояснений и вопросов по текущему разбору можно подключить **llama.cpp
с Qwen3.5-2B (GGUF Q4_K_M, около 1,28 ГБ)**. Во вкладке «Локальная ИИ»
есть адрес сервера, выбор модели, проверка соединения и сохранение настроек.
Qwen выбирает пункты из набора по теме вопроса; сервер удаляет посторонние
пункты и добавляет пропущенные темы. Можно спросить о несработавшем правиле
или формуле численного показателя. Нераспознанный вопрос требует уточнения.
Пояснение формируется из экспертного разбора: балл, статус, значения фактов
и основания не переписываются моделью. Ответ включается в Markdown.
При запуске интерфейса модель запускается автоматически, а подключение включается.
Уже работающий сервер используется повторно. При Ctrl+C завершается только
сервер модели, запущенный этим экземпляром приложения. Команды обычного анализа
и обучения работают без Qwen.
См. [установку, запуск и команды CLI](docs/LOCAL_AI.md).

## Темы и компоновки

Кнопка **«Интерфейсы»** в верхней панели открывает восемь вариантов
с мини-превью. Меняются палитра, типографика, плотность и расположение
панелей. Переключение сохраняет введённый профиль и готовый разбор.

| Интерфейс | Оформление и компоновка |
|---|---|
| Досье | Светлый фон, фиолетовый акцент; редактор слева, разбор справа |
| Ночной | Тёмно-синий фон и бирюза; разбор слева, редактор справа |
| Терминал | Графит и янтарь; моноширинный текст, плотные прямоугольные элементы |
| Бумага | Тёплые оттенки и книжные заголовки; редактор прокручивается вместе со страницей |
| Студия | Синий рабочий стол; крупные заголовки и выразительные контуры |
| Компактный | Узкий редактор, короткие отступы и больше данных в окне |
| Фокус | Широкий профиль сверху, разбор на всю ширину ниже |
| Карточки | Зелёные оттенки; замечания и вопросы отдельными плитками |

На мобильном экране панели складываются последовательно. Выбранный
интерфейс сохраняется в этом браузере через `localStorage`. Если браузер
запрещает сохранение, выбор действует в текущем сеансе. Черновик также
сохраняется в этом браузере; отдельную версию проекта сохраняйте кнопкой
**«Сохранить профиль .json»**.

Окно выбора поддерживает клавиатуру: Tab для перехода, Enter для выбора,
Esc для закрытия. [Галерея](docs/UI_GALLERY.png),
[ночной вариант](docs/UI_NIGHT.png), [плитки замечаний](docs/UI_CARDS.png).

## Реализовано

- **26 критериев, 28 правил** в редактируемой базе JSON.
- Продукт, реальные пользователи, спрос, экономика и конкуренты.
- Связь использования продукта с ценностью токена и права держателя.

- Прямой продукционный и обратный логический вывод.

- Фреймы с наследованием и редактированием; сеть **22 узла, 21 связь**, BFS.
- Браузерный интерфейс, CLI, отчёт, импорт и экспорт профиля.
- Восемь тем и компоновок с превью и сохранением выбора.

Это классический ИИ в форме экспертной системы. Произвольные формулировки
не всегда распознаются; их нужно уточнить в анкете. Введённые сведения
сохраняются локально в черновике браузера и в явно экспортируемых файлах.

## Расчёты и единицы

| Показатель | Формула |
|---|---|
| Капитализация | Цена USD × circulating supply |
| FDV | Цена USD × выбранный total или max supply |
| Доля обращения | Circulating / выбранная база FDV × 100% |
| Доля unlock | Объём unlock / circulating supply × 100% |
| Объём / капитализация | Объём 24ч USD / капитализация USD × 100% |

База FDV выбирается явно. Определения капитализации и FDV сверены
с материалами [CoinGecko о капитализации](https://www.coingecko.com/learn/what-is-market-cap-in-crypto)
и [FDV](https://www.coingecko.com/learn/what-is-fully-diluted-valuation-fdv-in-crypto).
Разные определения supply могут давать разные значения FDV, поэтому
база сохраняется в профиле и отчёте.

Пустое значение остаётся неизвестным; явный ноль сохраняется. Если результат
выходит за точность вычислений, показатель остаётся неизвестным с предупреждением.
Очень малые и большие значения отображаются в научной записи. USDT
не подставляется вместо USD. Если капитализация или FDV источника
отличаются от расчёта больше чем на 1%, выводится сообщение, а сигнал
по отношению FDV/капитализация не формируется до уточнения.

Учебные пороги: FDV/капитализация ≥3; обращение <25% базы FDV;
будущий unlock ≥10% обращения. Это фиксированные эвристики для
объяснимых сигналов, без предсказания движения цены. Нужны дата снимка
и дата unlock позже снимка, иначе сигнал будущей разблокировки не выводится.

## Как понимать оценку

Балл показывает **проработанность анализа по введённым сведениям**.
Нижняя граница учитывает известные положительные критерии, верхняя —
допускает положительные ответы по неизвестным. Веса открыты в базе знаний.
При явном отсутствии собственного токена токеномика исключается.
Неприменимые сведения о токене сохраняются в профиле и не участвуют в выводах.
Численные сигналы выводятся отдельно от балла.

Помощник не подтверждает введённые утверждения независимой проверкой.
Он не оценивает доходность и не предсказывает цену. Аудит, капитализация
и учебный балл сами по себе не подтверждают безопасность актива.
