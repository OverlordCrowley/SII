# Локальная ИИ через llama.cpp

Криптоскоп может дополнить экспертный разбор пояснением локальной языковой
модели и ответить на вопрос по этому разбору. По умолчанию подключение выключено.
Основной анализ, алиасы, расчёты и учебные классификаторы работают без llama.cpp.
Для Python дополнительные пакеты и API-ключи не нужны.

## Модель и запуск

Подходит [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B): 2 млрд параметров.
Вариант [GGUF Q4_K_M](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF/tree/main)
занимает около **1,28 ГБ** на диске. Оперативной памяти требуется больше:
помимо весов сервер хранит контекст и рабочие буферы. Скорость зависит от компьютера.
Здесь используется текстовый режим; картинки и vision-проектор не нужны.

Установите свежий [llama.cpp из официального репозитория](https://github.com/ggml-org/llama.cpp/releases).
Для Windows распакуйте подходящий архив и откройте терминал в папке с
`llama-server.exe`. Для macOS выберите arm64 на Apple Silicon или x64 на Intel;
можно установить через `brew install llama.cpp`. Для других платформ доступны
[инструкции сборки](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md).
Старые сборки могут не поддерживать Qwen3.5.

Запуск на macOS/Linux:

```sh
llama-server -hf unsloth/Qwen3.5-2B-GGUF:Q4_K_M --no-mmproj --alias qwen-local --host 127.0.0.1 --port 8080 -c 8192 -np 1 -ngl 99 --jinja
```

В PowerShell из папки распакованного llama.cpp:

```powershell
.\llama-server.exe -hf unsloth/Qwen3.5-2B-GGUF:Q4_K_M --no-mmproj --alias qwen-local --host 127.0.0.1 --port 8080 -c 8192 -np 1 -ngl 99 --jinja
```

Первый запуск скачает модель из Hugging Face и требует интернета. После
загрузки весов генерация работает локально. Для запуска только на CPU
замените `-ngl 99` на `-ngl 0`. Если модель уже скачана, вместо `-hf …`
используйте `-m "/путь/Qwen3.5-2B-Q4_K_M.gguf"` (в Windows — свой путь).
Оставьте терминал сервера открытым, для остановки нажмите Ctrl+C.
`--no-mmproj` предотвращает скачивание ненужного vision-проектора,
`-np 1` оставляет один слот генерации для экономии памяти.

## Подключение в интерфейсе

1. Запустите Криптоскоп, заполните профиль и нажмите «Проанализировать».
2. Откройте вкладку **«Локальная ИИ»** и включите подключение.
3. Адрес: `http://127.0.0.1:8080`. Имя модели: `qwen-local` или пустое поле
   для автоматического выбора из списка сервера. Адрес с `/v1` тоже допустим.
4. Нажмите «Проверить соединение», затем «Сохранить настройки».
5. Введите вопрос, например «Какие сведения о vesting ещё нужны?» и
   нажмите «Спросить ИИ». Без вопроса модель поясняет разбор и приоритетные проверки.
6. Сохраните отчёт `.md`: в нём будут ответ, вопрос, имя модели и адрес сервера.

Настройки также сохраняются при отправке вопроса. Они хранятся в
`.state/local_ai.json` и не попадают в Git. Таймаут генерации — 5–300 секунд,
по умолчанию 120. «Отменить запрос», правка профиля, смена примера или
повторный анализ отменяют ожидание в интерфейсе; поздний ответ не подменяет
новый разбор. llama.cpp может закончить уже начатую генерацию на своей стороне.
После перезагрузки страницы настройки сохраняются; профиль и ответ нужно
экспортировать отдельно.

## CLI

Команды выполняются из `crypto-project-assistant` (`python3` на macOS/Linux,
`python` на Windows):

```sh
python3 -m project_assistant local-ai configure --url http://127.0.0.1:8080 --model qwen-local --enabled
python3 -m project_assistant local-ai check
python3 -m project_assistant local-ai show
python3 -m project_assistant analyze examples/risky.json --local-ai --ai-question "Что нужно проверить в первую очередь?"
python3 -m project_assistant ask BTC --local-ai
python3 -m project_assistant local-ai configure --no-enabled
```

Флаг `--local-ai` явно включает модель для одного CLI-запроса, даже если
подключение в интерфейсе выключено. Без флага запросов к llama.cpp нет.
`analyze --json` включает ответ в JSON; `--output новый-отчёт.md` — в Markdown.
Отдельный файл настроек: `local-ai … --config-file путь.json`, для анализа —
`--ai-config путь.json`. Вопрос ограничен 1200 символами, ответ — 512 токенами.

## API и ограничения

Клиент использует [API llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md):
`GET /health`, `GET /v1/models`, `POST /v1/chat/completions`.
В запросе отключён thinking через `chat_template_kwargs.enable_thinking=false`.
Контекст включает краткое описание, значения критериев, основания,
замечания правил и вопросы. Полный файл профиля, браузерная история и
содержимое ссылок не отправляются. Принимаются только локальные HTTP-адреса
`127.0.0.1`, `localhost`, `::1`; перенаправления и системный HTTP-прокси отключены.

Сервер приложения предоставляет `/api/local-ai/config` (GET/POST),
`/api/local-ai/check` (POST настроек) и `/api/local-ai/explain`
(POST `{"project": {...}, "question": "..."}`). Для пояснения сервер заново
считает экспертный разбор из профиля. Ошибки модели возвращаются как 503,
ошибки ввода — 400. Проверка соединения доступна при выключенном подключении.

Языковая модель может ошибаться. Ответ не меняет факты, балл, статус,
доказательства правил или результаты Bayes/MLP. Она не подтверждает аудит,
не загружает котировки и не проверяет источники. Для неизвестных сведений
нужны собственные исследования пользователя. Это отдельный модуль от
учебной нейросети, обученной на синтетических профилях.

Если сервер недоступен — запустите `llama-server`, проверьте порт и дождитесь
загрузки. Если модель не найдена — очистите имя или введите id из `/v1/models`.
При таймауте увеличьте значение либо задайте более короткий вопрос. При
обрыве по лимиту длины задайте более узкий вопрос. Запускайте локальный
сервер без `--api-key`: ключи в этой интеграции не поддерживаются.

См. [проверку с настоящей Qwen, тесты и снимки](LOCAL_AI_QA_2026_10_07.md).
