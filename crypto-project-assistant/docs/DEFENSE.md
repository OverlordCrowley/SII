## Показ на 7–10 минут

1. Откройте GitHub и README. Назовите предметную область: полнота исследования
   криптопроектов по заявленным сведениям. Покажите критерии и правила JSON.
2. В терминале из папки приложения выполните `python -m project_assistant week415`.
   Покажите R16, AND/OR/NOT и отличие отрицания от отсутствующих данных.
3. Разберите прямую цепочку R01–R06 и дерево обратного доказательства.
4. Покажите наследование `crypto_project → defi → demo_protocol`, поиск слота,
   сохранение и повторную загрузку. Объясните, что родитель не изменяется.
5. Разберите сеть `project → token → supply → vesting → unlocks` и поиск BFS.
6. Откройте CSV, метаданные и `models/metrics.json`. Назовите размеры выборок,
   исключение дубликатов, признаки и два алгоритма. Покажите матрицы ошибок.
7. Запустите интерфейс. Введите `Bitcoin` или `BTC`: оба дают Bitcoin/BTC.
   Объясните, почему сведения о продукте не подставляются по названию.
8. Загрузите «Полный разбор», затем «Неполная токеномика». Раскройте объяснение,
   вкладку «Для защиты», сравните модели и правила, сохраните Markdown.
9. Покажите `python -m unittest discover -s tests -v`, тесты CI и ограничения.

Дополнительный показ на минуту: откройте вкладку «Локальная ИИ», проверьте
соединение с `llama-server`, задайте вопрос по R13 и сохраните ответ в Markdown.
Назовите Qwen готовой внешней языковой моделью, работающей локально.
Покажите, что экспертный балл и статус сохранились. Если модель не запущена,
используйте [сохранённый фактический отчёт](manual-qa-2026-10-07/local-ai-report.md).
Основной показ `week415` не требует llama.cpp или загрузки весов.

`week415` использует временные фреймы и сеть. Для отдельного показа команд
используйте `--state demo-frames.json` и `--state demo-network.json`, чтобы
сохранить пользовательскую модель приложения.
Повторное обучение запускается командой `python -m project_assistant train`;
на защите достаточно показать сохранённые веса и результат фактического обучения.

## Ответы на вопросы

**Почему это экспертная система?** Знания отделены от механизма вывода.
Система применяет правила к рабочей памяти, получает промежуточные заключения
и показывает посылки каждого результата.

**Чем отличаются прямой и обратный вывод?** Прямой расширяет факты из условий
правил. Обратный начинает с цели и проверяет необходимые посылки.

**Что означает неизвестно?** Сведений недостаточно. Это не доказательство
отрицательного факта. Помощник формирует уточняющий вопрос.

**Что обучает нейросеть?** Классификацию комбинаций фактов по статусам
исследования. 58 входов, 16 скрытых нейронов tanh, четыре выхода softmax.
Веса меняются методом SGD по перекрёстной энтропии.

**Можно ли считать 99% качеством оценки монет?** Нет. Это точность на 201
синтетическом примере, размеченном экспертными правилами. Реальные исходы
не измерялись. Поэтому модели показываются для сравнения с объяснимым выводом.

**Почему Байес ошибается чаще?** Он предполагает условную независимость
признаков внутри класса. В правилах есть сочетания признаков и цепочки условий.

**Что остаётся улучшить?** Реальные размеченные исследования с независимой
проверкой, валидация правил специалистом, расширение каталога алиасов и
извлечение утверждений из свободного текста. Эти задачи требуют новых данных.

**Чем Qwen отличается от учебной нейросети?** MLP студент обучает на
синтетических сочетаниях фактов и проверяет на отложенной выборке. Qwen3.5-2B
уже обучена разработчиком и подключена через llama.cpp для текстового
пояснения. Она может ошибаться и не меняет результат экспертных правил.

**Что опубликовано на GitHub?** Перед защитой сверить удалённый `main` с
локальным коммитом и открыть README, презентацию и workflow. Наличие
локального файла CI не подтверждает успешный запуск GitHub Actions.
