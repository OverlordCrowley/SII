# Ручная проверка и исправление Криптоскопа

Проверка и исправления от 7 октября 2026 года. Функции плана недель 4–8 присутствуют и проходят демонстрационные сценарии. Все обнаруженные ошибки исправлены и повторно проверены; ниже перечислены сценарии и доказательства. Для итогового семестрового проекта по-прежнему отсутствуют обучаемый модуль и презентация по теме Криптоскопа.

Проверено текущее рабочее дерево SII, включая незакоммиченные изменения, поверх коммита `12dcbe7`. Среда: macOS, Python 3.14.0, браузер Codex, локальный сервер `http://127.0.0.1:8765`. Интерфейс проверен при 1280 × 720 и 390 × 844. Действия выполнялись через реальные элементы формы: кнопки, поля, вкладки, файловый диалог и скачивание файлов. После проверки исправлены расчёты, обработка профилей, HTTP/CLI и браузерный интерфейс; добавлены регрессионные тесты. Ниже сохранены первоначальные сценарии и причины ошибок; их описания относятся к состоянию до исправлений.

## Дополнительные ошибки, исправленные после первичного аудита

Асинхронные ответы не учитывали порядок пользовательских действий: очистка могла возвращать старый отчёт, а медленный пример — перезаписывать последний выбор. Проверка с временным локальным сервером и задержками 3–4 секунды воспроизвела обе ошибки. Теперь новый запрос или очистка отменяет предыдущую операцию; ответ принимается только для неизменённой версии формы. Ошибки отменённых запросов не показываются. При редактировании во время обработки пользователь получает сообщение и может повторить анализ или сохранение.

Конечные входные числа могли давать бесконечное отношение либо нулевое произведение из-за ограничений float. Расчёт теперь оставляет такой показатель неизвестным и объясняет причину. Численные факты по нему не формируются. Явный ноль по-прежнему сохраняется. Малые метрики больше не округляются до отображаемого нуля, а крупные не растягивают строку.

Неприменимые токеновые сведения раньше исключались только из балла, но могли формировать заключения. Теперь при `has_token: false` они не участвуют и в логическом выводе. Профиль хранит исходные ответы и числа, чтобы их можно было использовать при последующем изменении ответа о наличии токена.

Глубоко вложенный JSON и недопустимый порт раньше могли завершаться traceback. Теперь они возвращают понятную ошибку. Адрес localhost раньше открывал страницу, но отклонял анализ с HTTP 403; оба локальных адреса разрешены, внешние источники запроса отклоняются.

Доказательства до исправления: [очистка со старым ответом](manual-qa-2026-10-07/reset-race.jpg), [перезапись последнего примера](manual-qa-2026-10-07/example-race.jpg). ## Ошибка сохранения изменённого профиля

Приоритет P2. Кнопка «Сохранить профиль .json» сохраняет последний проанализированный профиль. Правки формы после анализа теряются при экспорте без предупреждения.

1. Открыть «Полный разбор».
2. Изменить название на `QA — новое название перед сохранением`.
3. Сразу сохранить профиль, не нажимая «Проанализировать».
4. Открыть JSON: название осталось `Example Protocol — полный разбор`.

Ожидается сохранение текущей формы либо явное требование повторного анализа. До исправления экспорт читал `current.project`, а не содержимое формы: [index.html](../web/index.html). Markdown тоже оставался отчётом предыдущего анализа; интерфейс не отмечал его устаревание. После отдельного повторного анализа новое название экспортировалось корректно.

Сохранены [JSON со старым названием](manual-qa-2026-10-07/stale-export.json) и [снимок формы с правкой](manual-qa-2026-10-07/stale-export.jpg).

## Ошибка порога расхождения капитализации

Приоритет P2. Заявленная проверка отклонения больше 1% не работает для малых сумм: в коде есть дополнительный минимальный порог 1 USD.

1. Ввести цену `0.01`, circulating `10`, total и max `100`.
2. Ввести капитализацию источника `0.2`, выбрать базу max, задать дату и источник.
3. Нажать «Проанализировать».

Расчётная капитализация равна `0.1 USD`; указанная `0.2 USD` отличается на 100%. До исправления предупреждения не было, система показывала FDV `1 USD` и отношение `5 ×`. Ожидается предупреждение и неизвестное отношение до уточнения. Причиной был `max(1, abs(computed) * 0.01)` в [tokenomics.py](../project_assistant/tokenomics.py). Такое же сравнение использовалось для FDV.

Сохранены [профиль для воспроизведения](manual-qa-2026-10-07/small-cap.json) и [снимок результата](manual-qa-2026-10-07/small-cap-conflict.jpg).

## Ошибки обработки чрезмерного числа

Приоритет P2. Один и тот же JSON с `price_usd`, состоящим из 400 цифр 9, обрабатывается некорректно через три способа ввода.

- В браузере файл принимается без ошибки, цена становится пустой. Экспорт содержит `price_usd: null`. `JSON.parse` превращает число в Infinity, затем `JSON.stringify` отправляет null. Происходит молчаливая потеря исходного значения.
- CLI `python3 -m project_assistant analyze .../huge-number.json` завершает работу с кодом 1 и traceback `OverflowError: int too large to convert to float` вместо понятного сообщения о допустимом диапазоне.
- Прямой POST этого файла к `/api/analyze` закрывает соединение без HTTP-ответа; curl завершился с кодом 52. В журнале сервера тот же OverflowError. Процесс сервера остаётся живым; следующий нормальный анализ проходит.

Ожидается отклонение числа за пределами `0..1e30` с сообщением, а для HTTP — ответ 400. До исправления Python проверял `math.isfinite(value)` до проверки диапазона: [tokenomics.py](../project_assistant/tokenomics.py). Сервер и CLI не перехватывали этот OverflowError. Проверка конечности числа перед сериализацией в браузере отсутствовала.
