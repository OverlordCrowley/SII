Актуально на 14 октября 2026 года. Студент: Кораблев Максим Игоревич, Б-ИС 24/23 Р.

Криптоскоп исследует полноту сведений о криптопроекте. Пользователь указывает
факты о продукте, токене, команде и безопасности; программа применяет правила,
объясняет заключения и предлагает уточняющие вопросы. Исходные сведения
пользователя не проверяются автоматически по сайтам.

Все перечисленные ниже механизмы уже реализованы. Номер недели обозначает
задание учебного плана, а не дату написания кода. Реализация не подтверждает
сдачу задания, оценку или проведение защиты у преподавателя.

Для проверки в середине семестра сохранены [отчёты и реальные результаты по каждой неделе](results/weeks_04_09_2026_10_14/README.md).
Они предназначены для чтения на GitHub. Презентация потребуется только
к концу семестра и не входит в текущую сдачу недель 4–9.

## Как устроен проект

| Понятие | Простое объяснение | Пример |
|---|---|---|
| Факт | Утверждение о конкретном проекте | `audit_available = false`: пользователь указал «Аудит — Нет» |
| Критерий | Описание вопроса, на который нужно ответить | «Аудит доступен для изучения» |
| Правило | Условие и заключение «если …, то …» | R16: нет аудита и не разобраны права администратора → замечание |
| Вывод | Получение заключения из фактов и правил | Доказано `security_gap` |
| Фрейм | Объект или тип объекта со свойствами | DeFi-проект наследует валюту USD |
| Семантическая сеть | Понятия, соединённые отношениями | Проект → токен → предложение → vesting |

База `data/knowledge.json` хранит описания критериев и правила. Конкретные
ответы «Да / Нет / Неизвестно» находятся в профиле пользователя или в
`examples/*.json`. Определение критерия и его значение — разные данные.

| Файл | Роль |
|---|---|
| [knowledge.json](../data/knowledge.json) | 26 критериев, 28 правил, 6 типов фреймов, сеть из 22 узлов и 21 связи |
| [logic.py](../project_assistant/logic.py) | Логические операции и обратный вывод по заданной цели |
| [production.py](../project_assistant/production.py) | Прямой вывод из исходных фактов |
| [frames.py](../project_assistant/frames.py) | Наследование, чтение, поиск, создание и изменение слотов |
| [network.py](../project_assistant/network.py) | Узлы, связи и поиск пути по сети |
| [workbench.py](../project_assistant/workbench.py) | Пользовательские команды `frame` и `network` |
| [expert.py](../project_assistant/expert.py) | Объединение механизмов и проверка согласованности выводов |
| [assistant.py](../project_assistant/assistant.py) | Подготовка профиля, анализ, балл, вопросы и отчёт |

Основной путь: ввод → факты → правила → заключения → объяснения → рекомендации.
Фреймы добавляют описание типа проекта; сеть показывает связанные понятия.
Они не переписывают правила и веса балла. Qwen и обучаемые классификаторы —
дополнительные модули; задания недель 4–9 выполняет классическая экспертная часть.

## Неделя 5 — факты, правила и логический вывод

**Задание:** записать факты и логические правила, реализовать логический вывод.

**Что сделано:** `LogicalEngine` в `logic.py` реализует обратный вывод.
Он начинает с цели, ищет подходящее правило и проверяет необходимые посылки.
`query()` возвращает значение цели, `explain()` — дерево доказательства.

Пример настоящего правила R16:

```text
audit_available = false
admin_controls_known = false

NOT audit_available AND NOT admin_controls_known → security_gap
```

Оба факта явно отрицательные, поэтому замечание `security_gap` доказано.
Если значение факта не введено, цель может остаться недоказанной.

**Проверка:** `python3 -m project_assistant week48` показывает R16 в разделе
«НЕДЕЛЯ 5». Можно также выполнить `python3 -m project_assistant week56`.

**Что показать:** исходные факты, условие R16 и доказанную цель.
**Что сказать:** «Обратный вывод начинает с заключения и проверяет,
достаточно ли имеющихся фактов для его доказательства».

## Неделя 6 — AND, OR, NOT и объяснение

**Задание:** расширить вывод операциями AND, OR, NOT и объяснять результат.

**Что сделано:** парсер `parse()` строит дерево выражения без `eval`.
Приоритет операций: NOT, затем AND, затем OR; доступны скобки.
`evaluate_node()` вычисляет значения, `truth_table()` строит таблицу истинности.

| Операция | Значение |
|---|---|
| AND | Все необходимые условия должны быть истинными |
| OR | Достаточно истинности хотя бы одной ветви |
| NOT | Отрицание известного значения |

Неизвестность учитывается отдельно: `NOT unknown = unknown`,
`false AND unknown = false`, `true OR unknown = true`.
Профиль допускает `null`; перед выводом неизвестные факты исключаются из
рабочей памяти. Отсутствующий факт возвращает неизвестное значение.
NOT разрешён над исходными фактами, что сохраняет монотонность прямого вывода.

Правило R13:

```text
has_token AND (NOT vesting_disclosed OR NOT unlock_schedule_known)
→ unlock_opacity
```

Если токен есть и пользователь явно указал «Vesting — Нет», правило может
сработать даже при неизвестном значении графика: одна ветвь OR уже истинна.
Отсутствие сведений сразу о двух критериях не заменяется двумя ответами «Нет».

`explain()` строит доказательство, `proof_lines()` в `assistant.py` делает его
читаемым. В случае OR сохраняется достаточная подтверждающая ветвь.
В браузере откройте пример и нажмите «Показать объяснение».

**Что показать:** операции в `week56`, таблицу из 8 строк и объяснение R16.
**Что сказать:** «Система различает отрицание и недостаток сведений,
а каждое заключение можно проверить по его посылкам».

## Неделя 7 — продукционная система и прямой вывод

**Задание:** сформировать базу продукционных правил и реализовать прямой вывод.

**Что сделано:** `ProductionEngine.run()` в `production.py` получает исходные
факты, проверяет правила по приоритету и добавляет истинные заключения.
Новые заключения могут использоваться следующими правилами. Проверка
повторяется, пока новые факты перестают появляться.

В полном профиле R01–R05 выводят промежуточные заключения о продукте,
токене, предложении, материалах безопасности и источниках. R06 использует
эти заключения вместе с дополнительными исходными фактами и выводит
`research_ready`.

Трасса `trace` хранит номер шага, правило, условие, посылки и заключение.
`ExpertSystem.infer()` проверяет каждый полученный вывод обратным механизмом.
При конфликте с явно отрицательным заключением выдаётся ошибка.

**Проверка:** раздел «НЕДЕЛЯ 7» команды `week48`; пример «Полный разбор»
в браузере. Ожидаются R01–R06 и статус основы для углублённого сравнения.

**Что сказать:** «Прямой вывод начинает с фактов и получает доступные
заключения; обратный вывод начинает с выбранной цели».

## Неделя 8 — фреймы, свойства и наследование

**Задание:** описать объекты, свойства и связи, реализовать наследование.

**Что сделано:** `FrameStore` в `frames.py`. Фрейм содержит родителя `parent`
и свойства `slots`. Базовый `crypto_project` задаёт метод исследования,
валюту USD и требования к источникам. Его потомки: `defi`, `layer1`,
`layer2`, `infrastructure`, `gaming`.

Пример наследования:

```text
crypto_project → defi → demo_protocol
```

| Свойство | Значение | Откуда получено |
|---|---|---|
| `quote_currency` | `USD` | `crypto_project` |
| `focus` | Исследование fees, дохода, TVL и прав токена | `defi` |
| `name` в учебном экземпляре | Учебный протокол | `demo_protocol` |

`describe()` собирает свойства по цепочке родителей и указывает происхождение
каждого значения. Локальное переопределение изменяет потомка, сохраняя
значение родителя. Несуществующие родители и циклы наследования отклоняются.
Связь с понятием сети в демонстрации представлена слотом `related_node`.

**Проверка:** `python3 -m project_assistant frame show defi`; раздел «НЕДЕЛЯ 8»
команды `week48` создаёт временный экземпляр и проверяет переопределение.

**Что сказать:** «Объект наследует общие свойства типа и может иметь
собственные значения; источник каждого слота виден в описании».

## Неделя 9 — программа работы с фреймами

**Задание:** добавить поиск и изменение свойств объектов.

**Что сделано:** пользовательские команды `workbench.py`, использующие
методы `create`, `describe`, `find` и `set` класса `FrameStore`.

| Команда | Действие |
|---|---|
| `frame create` | Создание фрейма с родителем |
| `frame show` | Просмотр собственных и унаследованных свойств |
| `frame set` | Добавление или изменение слота |
| `frame find` | Поиск по значению, включая наследуемые свойства |

Для показа используйте отдельный файл, чтобы не менять модель приложения:

```sh
python3 -m project_assistant frame --state demo-frames.json create my_protocol defi
python3 -m project_assistant frame --state demo-frames.json set my_protocol reviewed true
python3 -m project_assistant frame --state demo-frames.json find reviewed true
python3 -m project_assistant frame --state demo-frames.json show my_protocol
python3 -m project_assistant frame --state demo-frames.json find quote_currency '"USD"'
```

Ожидается: `my_protocol` создан; `reviewed` равно `true`; поиск `reviewed`
возвращает `my_protocol`; просмотр показывает валюту USD из общего родителя.
Поиск валюты включает потомков, получивших USD по наследованию.
Команды каждый раз загружают файл заново, поэтому этот пример также
проверяет сохранение и повторную загрузку.

Запустите `create` один раз для нового имени. При повторе программа сообщит,
что имя уже существует; остальные команды можно повторять.
Значения передаются как JSON: `true` — логическое значение, `'"USD"'` —
строка в оболочке macOS/Linux. Имена новых слотов имеют вид `reviewed`.
Тип существующего слота сохраняется; поиск различает типы значений.

Без `--state` используется `.state/frames.json`. После изменения этого файла
перезапустите браузерный сервер, чтобы он загрузил новую модель. Веб-редактора
фреймов нет: изменение выполняется через CLI. Эти операции меняют описание
объекта и не переписывают правила оценки.

**Что показать:** пять команд, найденный объект и сохранённый JSON.
**Что сказать:** «Программа создаёт объекты, изменяет свойства, ищет их с
учётом наследования и сохраняет изменения между запусками».
